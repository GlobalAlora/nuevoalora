01 — QUÉ ES

Strix, en criollo

No es un scanner que tira falsos positivos. Son agentes de IA que corren tu app de verdad, encuentran fallas y las explotan con una prueba de concepto real, como haría un pentester humano.

🕷️

Explota, no solo detecta

Genera exploits funcionales (PoC) en vez de alertas genéricas sin validar.

🧩

Cubre el OWASP Top 10

SQLi, XSS, IDOR, SSRF, auth bypass, lógica de negocio y más.

🤖

Multi-agente

Varios agentes se coordinan: reconocimiento, explotación y validación en paralelo.

🛠️

Auto-fix

Puede generar el parche de seguridad y dejarlo listo como pull request.

02 — CÓMO CORRERLO

Elegí tu camino

Hay dos formas de usarlo desde Claude Code. Si es tu primera vez, arrancá por la Managed — no necesitás Docker ni tu propia API key de LLM.

1

Creá tu cuenta gratis

Andá a app.strix.ai y registrate. No hace falta instalar nada localmente ni tener Docker corriendo.

2

Desde la terminal, parado en la carpeta de tu app:

Le indicás en lenguaje natural qué querés testear, usando el skill managed (vía API, sin infraestructura local):

Usá Strix managed para pentestear mi app en producción, enfocate en autenticación e IDOR
4

Revisá los hallazgos

03 — DUDAS COMUNES

Antes de que preguntes

¿Si se lo pido en el chat de Claude Code, usa la sesión de Claude que ya tengo abierta?

No. Strix es un proceso independiente por fuera de Claude Code. Claude Code solo ejecuta el comando; Strix necesita su propia configuración (managed = cuenta en app.strix.ai, local = Docker + API key propia).

¿Cuál conviene si nunca lo usé?

Managed. Cero fricción: sin Docker, sin variables de entorno, sin gastar tu propia API key de LLM en cada escaneo.

¿Puede arreglar lo que encuentra?

Sí — el skill "fix-security-vulnerabilities-with-strix" genera el parche y vuelve a escanear para confirmar que la falla quedó resuelta.

¿Sirve para meterlo en el pipeline de CI/CD?

Sí, con el skill "ci-security-scanning-with-strix" escanea automáticamente cada pull request y bloquea código inseguro antes de mergear.

⚠️

Uso autorizado únicamente

Strix ejecuta ataques reales contra el objetivo que le indiques. Corrélo solo contra aplicaciones propias, o con permiso explícito y por escrito del dueño.

Testear sistemas de terceros sin autorización es ilegal en la mayoría de las jurisdicciones. La responsabilidad de tener autorización es enteramente tuya.
